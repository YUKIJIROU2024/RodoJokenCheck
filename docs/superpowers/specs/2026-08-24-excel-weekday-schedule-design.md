# Excel版（generate_check_sheet.py）：①労働時間の曜日別所定労働時間 設計

- 日付: 2026-08-24
- 対象: `generate_check_sheet.py`（Excel版チェックシート生成スクリプト）。
- 前提: Web版（`index.html`）の同名機能はすでに `main` にマージ済み（PR #1、
  `docs/superpowers/specs/2026-08-23-weekday-schedule-design.md` 参照）。
  本specはその設計思想をExcelの数式ベースの制約の中で再現する。

## 背景・目的

Web版で「曜日ごとに始業・終業・休憩を設定できる」機能が追加された。Excel版
（HelloWork受付・事業所配布用）にも同じ検証能力を持たせる。

Excel（マクロなしの `.xlsx`）はJSのような動的なUI表示切替ができないため、
Web版の「チェックを入れると行が現れる」というUI挙動はそのまま持ち込めない。
この制約に対する対応方針をユーザーと確認済み（下記「UI方式」）。

## 要件（ユーザー確認済み）

1. **UI方式**: 常に7曜日分の入力行を表示し、「曜日ごとに設定する」切替セル
   （はい/いいえ、既定=いいえ）で数式側の参照先を切り替える。行の表示/非表示
   は行わない（④の`wd{i}`休日セルと同じ「常時7セル表示」パターンに合わせる）。
2. **互換性**: 判定詳細欄で「超過している曜日を列挙」する部分は `TEXTJOIN`
   関数（Excel 2019/365以降）を使ってよい。古いExcelとの互換性は優先しない。
3. Web版と同じ年間総労働時間の算出方式（週合計÷週就業日数の平均値）を踏襲。
4. 祝日・最低賃金テーブル自体の更新、⑤変形労働時間制との連動強化は対象外。

## データ層（新規セル・行）

`build_check_sheet()`の「◆ 共通設定・共通計算」セクション内、既存の
`startTime`/`endTime`/`breakTime`/`startMin`/`endMin`/`dailyMin`の直後に追加:

- `useWeekday`（切替、`はい`/`いいえ`、既定`いいえ`）
- 曜日ごと（i=0..6、0=月〜6=日、④の`wd{i}`と同じ並び）に3つの入力セル:
  `dayStart{i}`（時刻）、`dayEnd{i}`（時刻）、`dayBreak{i}`（分・数値）
- 曜日ごとに1行の計算セル `dayMin{i}`（「その曜日の有効な所定労働分数」）:
  - `useWeekday`が「いいえ」の間は既存の共通`dailyMin`セルの値を返す
  - 「はい」のときはその曜日自身の`dayStart{i}`/`dayEnd{i}`/`dayBreak{i}`から、
    既存の`dailyMin`と同じ計算（翌日にかかる場合の24時間補正込み）で算出する
  - 例（Pythonで生成する数式の骨子）:
    ```
    =IF(useWeekday="はい",
        MAX(0,(IF(dayEnd{i}<dayStart{i},dayEnd{i}+1,dayEnd{i})-dayStart{i})*24*60-dayBreak{i}),
        dailyMin)
    ```
  - これがWeb版の`getDaySchedule(i)`に相当する「単一の判断ポイント」であり、
    以降の集計（①1-1/1-2、③3-1）はすべてこの`dayMin{i}`だけを参照する。
    共通の`startTime`/`endTime`/`breakTime`や`dayStart{i}`等を直接参照する
    箇所を他に作らない。

既存の`wd0`〜`wd6`（④の休日セル、現状は`dailyH`セルより後ろに定義されている）
は、`weeklyH`・`dailyH`・`maxDailyH`の集計が参照する必要があるため、Python
コード上の定義順を「共通設定・曜日別入力の直後」に前倒しする（物理的な行の
並び順が変わるだけで、`wd{i}`自体の入力内容・選択肢・ラベルは変更しない）。

## ①1-1（1日8時間・労基法32条2項）

新規行 `maxDailyH`（就業日の中の最大1日時間）を追加:

```
maxDailyMin = MAX((wd0="いいえ")*dayMin0, (wd1="いいえ")*dayMin1, ..., (wd6="いいえ")*dayMin6)
maxDailyH   = maxDailyMin/60
```

（休日の曜日は`(wd{i}="いいえ")`が0になり、その曜日の値は最大値の計算に
寄与しない。全曜日が休日の場合はmaxDailyH=0となり判定は○——Web版と同じ
挙動で、Web版の最終レビューでも「回帰ではない・既存挙動の踏襲」として
容認済み。）

1-1の判定式を`dailyH<=8`から`maxDailyH<=8`に変更。詳細欄はTEXTJOINで
超過している曜日を列挙する:

```
=TEXTJOIN("・",TRUE,
  IF(AND(wd0="いいえ",dayMin0/60>8),"月",""),
  IF(AND(wd1="いいえ",dayMin1/60>8),"火",""),
  ... (7曜日分)
)&"曜日が8時間超過"
```

（切替=いいえのときは全曜日の`dayMin{i}`が共通`dailyMin`と同値になるため、
超過していればいずれか1曜日だけが該当し、実質的に現状のメッセージと
同じ意味になる。）

## ①1-2（週40/44時間・労基法32条1項）

`weeklyH`の数式を、現状の`dailyH*weeklyWorkDays`（共通値×日数の掛け算）
から、就業日ごとの`dayMin{i}`の合計に変更:

```
weeklyH = ((wd0="いいえ")*dayMin0 + (wd1="いいえ")*dayMin1 + ... + (wd6="いいえ")*dayMin6) / 60
```

判定式・詳細欄の構造は変更しない（`weeklyH`と`weeklyLimit`の比較のまま）。

**回帰保証**: 切替=いいえのとき、全`dayMin{i}`=共通`dailyMin`なので、
新weeklyH = 共通dailyMin × 就業日数 ÷ 60 = 旧weeklyH（`dailyH*weeklyWorkDays`）
と数式的に一致する。

## ①1-3（年間総労働時間・参考）／⑧最低賃金（日給制）

既存の`dailyH`セルの数式を「共通の1日時間（`dailyMin/60`）」から
「週合計÷週就業日数の平均値」に置き換える:

```
dailyH = IF(weeklyWorkDays>0, weeklyH/weeklyWorkDays, 0)
```

`annualWorkH`（1-3で使用）と⑧の`hourlyRateBasic`（日給制の時間換算）は
どちらも既存の`dailyH`セルを参照しているため、**この1箇所を直すだけで
1-3と⑧の両方が自動的に平均ベースになる**。⑧側の数式（`hourlyRateBasic`
以降）・⑧-2・⑧-3は一切変更不要。Web版のTask 4と同じ「変数名は保ったまま
参照元だけ差し替える」設計。

## ③3-1（休憩時間の長さ・労基法34条1項）

現状は共通の`dailyMin`から必要休憩を1回だけ算出し、共通の`breakTime`と
比較している。これを曜日ごとの判定に変更する:

```
各曜日iについて:
  dayReqBreak{i} = IF(dayMin{i}>480, 60, IF(dayMin{i}>360, 45, 0))
  dayEffBreak{i} = IF(useWeekday="はい", dayBreak{i}, breakTime)
  dayPass{i}     = OR(wd{i}="はい", dayEffBreak{i}>=dayReqBreak{i})

j3_1 = IF(AND(dayPass0, dayPass1, ..., dayPass6), "○", "✗")
```

（休日の曜日は`OR`の左辺が真になるため自動的にパス扱い＝集計に影響しない。）

詳細欄はTEXTJOINで休憩不足の曜日を列挙する（1-1と同じパターン）。
切替=いいえのときは全曜日の`dayMin{i}`/`dayEffBreak{i}`が共通値と同値に
なるため、現状の判定と数式的に一致する。

## テスト観点

- 切替=いいえ（既定）で、①1-1/1-2/1-3・③3-1・⑧の判定・数値が既存の
  `rodo-joken-check.xlsx`と完全に一致すること（回帰確認）。
- 切替=はい・全曜日同じ値 → 切替=いいえと同じ結果になること。
- 切替=はい・一部曜日だけ短時間（例: 土曜3時間・休憩0分）→ 1-2の週合計が
  正しく減ること、3-1で土曜だけ休憩不要判定になること。
- 切替=はい・ある曜日が8時間超（例: 月曜9時間）→ 1-1が✗になり、詳細欄に
  その曜日が明示されること。
- ④で休日にしている曜日は、曜日別入力があってもmaxDailyH/weeklyH/3-1の
  集計から除外されること。
- 全曜日が④で休日の場合、maxDailyH=0・weeklyH=0でエラーにならず、
  1-1/1-2は○、⑧は既存の`dailyH<=0`ガードにより△になること
  （1-1/1-2と⑧の判定が食い違う点はWeb版でも既知・容認済みの挙動で、
  今回新たに悪化させるものではない）。
- ⑧の日給制の時間換算が、1-3が表示する平均1日時間と同じ数値を使っている
  こと（`dailyH`セルの参照が共通のため数式的に保証される）。
